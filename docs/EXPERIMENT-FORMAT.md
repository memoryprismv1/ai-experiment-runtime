# Experiment format v1.0

Experiment definitions are JSON so they can be validated, hashed, committed, and generated by scripts without requiring a YAML parser.

Top-level fields:

- `schema_version`: currently `1.0`.
- `experiment_id`, `title`: stable identity and human-readable purpose.
- `provider`: shared provider configuration for the controlled pair.
- `system_prompt`: common instruction applied to both conditions.
- `tasks`: an array of `{ "id", "prompt" }` inputs.
- `conditions`: exactly two conditions, labelled `A` and `B`.
- `trials_per_task`: independent repetitions, from 1 to 100.
- `random_seed`: optional integer seed for reproducible condition execution order; when omitted, a seed is generated and preserved in the report.

Each condition may define `system_instruction`, `resources`, and `mock_responses`. A resource is a UTF-8 text file whose path is relative to the experiment JSON. Its exact byte hash is stored in the run manifest. Resources are included in the condition's system prompt and treated as experimental inputs, not as trusted instructions to the runtime itself.

Provider types:

- `mock`: deterministic test fixture; condition-specific `mock_responses` maps task IDs to outputs.
- `openai-compatible`: chat-completions API with `base_url`, `model`, optional `temperature`, `max_tokens`, `timeout_seconds`, and `api_key_env`. Credentials are read from the environment and never copied into the manifest.

The first release intentionally has one shared provider block. This makes model identity and provider settings controlled across A/B. Testing different models is a future multi-factor extension; do not disguise a provider difference as a skill-only comparison.

See `schemas/experiment.schema.json` for the machine-readable structure and `examples/` for runnable and real-model templates.
